# SDK bindings

The generated provider talks to Infrahub through a [genqlient](https://github.com/Khan/genqlient)-built SDK. The SDK's scalar bindings must match the Terraform types the generator emits, or the generated provider will not compile.

## Why bindings matter

When you turn on [schema typing](schema-typing), the generator emits typed accessors:

- `Number` attributes use `ValueInt64()` and `types.Int64Value`.
- `DateTime` is rendered as `types.String`, because the plugin framework has no DateTime type.

For that generated code to compile, the SDK must hand back matching Go types: `int64` for `BigInt` and `string` for `DateTime`.

## Update `sdk/genqlient.yaml`

In the [provider template](https://github.com/opsmill/infrahub-terraform-provider-template) the SDK is built locally from `sdk/genqlient.yaml`. Its `bindings:` block must line up with the types this generator emits:

```yaml
bindings:
  BigInt:
    type: int64
  DateTime:
    type: string
```

The template ships these defaults as `string` and `time.Time`, which will not compile against typed output. Update them and regenerate the SDK:

```bash
make generate_sdk
```

## No custom marshaler is needed

Infrahub's `BigInt` is graphene's built-in scalar (`serialize = coerce_int`), so it is sent and received as a JSON number, which genqlient maps cleanly to `int64`. `DateTime` is an ISO-8601 string. The `int64` type covers values up to roughly 9.2 x 10^18, matching Terraform's `types.Int64`, so no custom marshaler is required.
